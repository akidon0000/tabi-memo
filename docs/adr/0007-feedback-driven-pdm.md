# 0007: FB 起点の進め方を pdm スキルにして、要件確定までは実装しない

- 状態: 有効
- 読み手: 将来の自分・エージェント
- 日付: 2026-10-04

## 決定

- TestFlight の FB を起点に、仕分け → ヒアリング → 要件の確認 → 実装 → 配信 → 検証の順で進める。進行役は `.claude/skills/pdm/`(`/pdm`)。
- 要件が曖昧な項目は、`pv-grilling`(質問を frontier 単位のラウンドで出し、推奨回答を添える方式)で詰める。ユーザーが入口で使う `pv-grill-me` はモデルから自動起動できないため、その中身の `pv-grilling` を呼ぶ。
- FB の原文は `docs/feedback/`、項目の状態は `docs/backlog.md`、要件は `docs/requirements/` に置く。画面の挙動は既存の `docs/specs/`、判断は `docs/adr/`。
- **ユーザーが要件を確認するまで実装しない。** 外へ出る連絡(テスターへの通知など)は、文面と宛先を見せて確認してから行う。

## 理由

実機テストの声は、解決策の形(ボタンを足して等)で届きやすい。困りごとに戻して要件を決めてから作ると、的を外した実装のやり直しが減る。判断を人に残し、調べることはエージェントが担う。

## 割り切り

- FB の取得は TestFlight(`asc testflight feedback`)とチャット貼り付けが中心。外部の要望窓口は扱わない。
- スキルは本リポジトリ専用。他のアプリでも使いたくなったら、hq の共通スキルへ上げる。
