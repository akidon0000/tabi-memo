# 0014: 写真を結ぶ線は、MapKit の経路検索で道なりにする

- 状態: 有効
- 読み手: 将来の自分・エージェント
- 日付: 2026-10-05

## 決定

> 2026-10-05 追記: 線の見た目は、白い破線から青い実線に変えた(軌跡の緑の線は描かない)。経路の求め方の決定は変わらない。([要件 0004](../requirements/0004-route-edit-mode.md))

写真を撮影順に結ぶ白い破線([FB-2](../backlog.md))は、隣り合う写真ごとに MapKit の経路検索(`MKDirections`)で道なりの経路を求めて描く。徒歩で求め、無ければ車で求める。求められない区間は直線にする。経路は区間(出発と到着の座標の組)ごとに、アプリが動いている間だけ覚える。

構成は次のとおり。ADR 0009 の層に沿う。

| 層 | 置くもの |
|---|---|
| Domain | `RouteFinding`(経路を求めるプロトコル)、`FindRouteUseCase`(求められなければ直線を返す)、`RouteSegment`、`PhotoPath`(区間ごとの経路をつなぐ純粋な計算) |
| DataLayer | `MapKitRouteFinder`(`MKDirections` で求める実装) |
| Features | `TripMapViewModel` が足りない区間を順に求めて持ち、地図が `photoPath` を描く |

## 背景

線が直線だと、道や川を無視して見える。旅の経路として自然に見せたい、という依頼が出た(2026-10-05)。

## 比較

| 案 | 内容 | 採否 |
|---|---|---|
| A. 直線のまま | いまの実装 | 不採用(依頼と合わない) |
| B. MapKit の経路検索 | 標準。徒歩・車の経路が返る | 採用 |
| C. Google Maps の Directions API | 経路の質は高いが、APIキー・課金・外部通信が要る。このアプリは外部ライブラリも通信先も持たない | 不採用 |
| D. 位置情報(HealthKit など)から実際に通った経路を取り込む | 道なりであり、実際に通った道になる | 見送り(取り込み元を決めてから、別の要件で扱う) |

## 割り切り・注意

- 電車・飛行機の区間は道なりにならない(直線のまま)。MapKit の経路検索は徒歩と車だけ。
- 通る道は「経路検索が出した道」で、実際に通った道とは限らない。
- 通信が要る。圏外のときは直線のままで、経路は覚えないので、アプリを開き直すと求め直す。求められなかった区間は、アプリを閉じるまで求め直さない(圏外のまま何度も呼ばないため)。
- 経路検索には呼び出しの回数の上限がある。区間ごとに1回だけ呼び、写真を足したときは足した区間だけ求める。
- 道なりの経路そのものは端末に保存していない(開き直すと求め直す)。ユーザーが直した経由点は保存する([ADR 0015](0015-route-waypoints.md))。

## 見直しのタイミング

- 経路の取得が遅い・失敗が多いと分かったとき(保存する、移動手段を選べるようにする)。
- 位置情報の取り込み(D)を始めるとき。
