# 0015: 直した経路は、写真の組ごとの経由点として保存する

- 状態: 有効
- 読み手: 将来の自分・エージェント
- 日付: 2026-10-05

## 決定

白い破線を直した内容は、「通ってほしい点(経由点)」として、写真の組(出発の写真 ID と到着の写真 ID)ごとに SwiftData に保存する。道なりの経路は、出発 → 経由点 → … → 到着を区間に分けて、区間ごとに求める([ADR 0014](0014-route-along-roads.md) の経路検索を、区間の単位で使う)。

| 層 | 置くもの |
|---|---|
| Domain | `RouteEdit`(写真の組と経由点)、`Trip.routeEdits`、`RouteEditRepository`、`SetRouteWaypointsUseCase`、`PhotoPath` の区間分け |
| DataLayer | `RouteEditRecord`(`TripRecord` に属する)、`SwiftDataRouteEditRepository` |
| Features | `RouteViewModel`(経路の状態と編集)、編集モードの View と、当たり判定 `RouteHitTest` |

あわせて、経路まわりの状態(区間ごとの経路・編集モード・経由点の追加移動削除)を `TripMapViewModel` から `RouteViewModel` に分けた。型の本体の行数の上限(150行)を守るため。

## 背景

直した経路が、アプリを閉じると消えるのでは使えない(依頼で「保存する」と確認した)。

## 比較

| 案 | 内容 | 採否 |
|---|---|---|
| A. 写真の組(ID)ごとに経由点を持つ | 写真の位置を動かしても、経由点は残る | 採用 |
| B. 区間の座標をそのまま保存する | 道なりの経路の全点を持つ | 不採用(写真を動かすと合わなくなる。保存が大きい) |
| C. 保存しない | アプリを閉じると自動の経路に戻る | 不採用(依頼と合わない) |

## 割り切り・注意

- 保存データの形が変わる(`RouteEditRecord` の追加)。既存のデータは、そのまま開ける(モデルを足しただけの軽量な移行)。ただし実機の既存データでの移行は未確認。
- 写真を取り除く・撮影順が変わるなどで写真の組が変わると、組が合わない直しは使われなくなる。消えずに残る(写真を戻せば、直しも戻る)。写真を完全に消しても、直しは掃除していない。
- 経由点の座標は、緯度と経度を別の配列で持つ(SwiftData が座標の配列を持てないため)。
- 経路編集モードの出入り(地図を止める案・止めない案)は2案を実装して見比べている。決まったら1つにする([要件 0004](../requirements/0004-route-edit-mode.md))。

## 見直しのタイミング

- 実機の既存データで移行に失敗したとき。
- 写真の組が変わったときの、経由点の引き継ぎが必要になったとき。
