# 0002: システムのシートをやめ、自前の下部パネルにする

- 状態: 有効
- 読み手: 将来の自分・エージェント
- 日付: 2026-10-02

## 決定

写真の詳細は、SwiftUI の `.sheet` + `presentationDetents` ではなく、地図の上に重ねる自前のビュー（`CustomSheetView`）で出す。高さはコンパクト・ハーフ・全開の3段階で、ドラッグとバーのタップで切り替える。

## 背景

最初は `.sheet` で作った。次の要望が出て、システムのシートでは実現できなかった。

- コンパクト時に、バナーの右へ**別のガラスの円（追加ボタン）**を並べたい。シートの外枠はシステムが描くので、ボタンが枠の外に出ず、薄い板が重なって見えた。
- シートの高さに連動して、ヘッダー（写真・タイトル・角丸・余白）を滑らかに変形させたい。
- 全開では上のセーフエリアの下まで届く白い画面にし、ハーフでは角丸を端末の画面角に合わせたい。

## 比較

| 案 | 内容 | 結果 |
|---|---|---|
| A. `.sheet` + 背景透明 | 背景色は消せるが、外枠の形・影・半透明はシステム固定 | ボタンと枠が重なる。不採用 |
| B. 追加ボタンだけ地図側に置く | シートはそのまま。ボタンはシートの上に浮かぶ | 「横並び」にならない。不採用 |
| C. 自前の下部パネル | 全部こちらで描く | 採用 |

## 失うもの（C のコスト）

- システムの detent の吸着、背景操作の制御、`interactiveDismissDisabled` などが使えない。吸着は速度込みの到達点で一番近い高さへ丸める実装を自前で持つ。
- 縦ドラッグ・スクロール・左右スワイプが競合する。全開ではヘッダーのタッチを下のスクロールに通し、縦ドラッグは上部の固定行（バー）だけが受ける。

## 見直しのタイミング

システムのシートが、枠の外に別ビューを置けるようになったとき。
