# 0019: トリップを複数持ち、一覧を入口にする

- 状態: 有効
- 読み手: 将来の自分・エージェント
- 日付: 2026-10-11

## 決定

アプリの最初の画面をトリップの一覧にする。トリップを選ぶと、これまでの地図画面が開く。トリップは、一覧で作り、名前を変え、削除できる。削除は、写真と同じく論理削除(`removedAt`)で、保持期間(`PhotoRetention.days`、いま7日)のあいだ「最近削除したトリップ」から戻せる。デモのトリップは新しく入れない(すでに入っている端末では、ほかのトリップと同じに扱う)。

## 背景

これまでは、起動すると軌跡のあるいちばん新しいトリップの地図が開き、トリップは1つしか扱えなかった([ADR 0001](0001-map-screen-only.md) で地図画面だけに絞ったため)。旅ごとに分けて残せなかった。[要件 0007](../requirements/0007-trip-list.md) で、一覧・作成・名前変更・削除を決めた。

## 決めたこと・割り切り

- 地図画面は、開くトリップの ID を受け取る(`ObserveCurrentTripUseCase` をやめ、`ObserveTripUseCase(tripID:)` を使う)。画面の遷移は `NavigationStack` で、地図画面は自前の戻るボタンを持つ(ナビゲーションバーは出さない)。
- 一覧の画面は `TripListFeature`。地図画面(`TripMapFeature`)に依存し、地図画面の作り方は App が渡す。
- 保存の形は、`TripRecord` に `removedAt`(任意)を足すだけ。軽量な移行で済む。
- 削除したトリップを完全に消す(`PurgeExpiredTripsUseCase`)のは、一覧を開いたとき1回。
- 空のトリップ(写真0枚)の地図は、現在地の周り(許可が無ければ東京)を出す。
- 見た目の未決定(一覧の見た目・並び順、戻るボタンの位置、「+」の選び方)は、アプリ内の設定(`AppearanceSettingsView`)で切り替えて見比べる。決めたら、使わない案を消す。

## 見直しのタイミング

- トリップが増えて、一覧の検索や並べ替えが要るようになったとき。
- 位置の記録(トリップの開始・終了)を入れるとき。
