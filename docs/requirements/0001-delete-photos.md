# 要件 0001: 写真を削除する(最近削除した項目から7日間は戻せる)

- 状態: 確定(2026-10-04)。実装済み・TestFlight 未配信
- 元の FB: [FB-1](../feedback/2026-10-04.md)「削除する動線がない」
- 日付: 2026-10-04

## 困りごと

地図に置いた写真を、あとから消す方法がない。テストで入れた写真や、間違えて入れた写真が残り続ける。

## 要件

- 地図画面の右上に、常に「…」ボタンを置く(44pt のガラスの丸ボタン)。メニューは「最近削除した項目」だけ。
- 全開のパネルでも、同じ「…」が右上に出る(左上は閉じる×)。
- **2026-10-04 変更**: 写真の削除は「…」ではなく、ハーフ・全開のパネルの写真の右下に出る、ペンとゴミ箱を1つにまとめたガラスの楕円から行う(3つの置き場所を試して、写真の右下に決めた)。ペンは編集シート(日時・場所・タイトル・メモ)を開く。
- ゴミ箱を押すと確認を出す(Apple の写真アプリの形)。

  > この写真は、ライブラリから削除されます。削除した写真は「最近削除した項目」に7日間残ります。
  > ［写真を削除(赤文字)］［キャンセル］

- 削除すると、地図からピンが消える。パネルは、撮影順で隣の写真(次があれば次、なければ前)に切り替わる。最後の1枚だったらパネルが閉じる。
- 削除した写真は、画像・日時・位置・タイトル・メモをすべて残したまま隠す。地図・並べ替え・隣の写真への移動・位置の初期値の計算には出さない。
- 「最近削除した項目」の一覧:
  - 各行に、サムネイル、タイトル(無ければ「タイトルなし」)、撮影日時、「あと◯日」を出す。
  - 行ごとに「元に戻す」(元の場所・日時・メモのまま地図に戻る)と「完全に削除」(確認を出す)を置く。
  - 何も無いときは「最近削除した項目はありません」を出す。
- 削除から7日たった写真は、完全に消す。消す処理は、アプリを開いたときと、一覧を開いたときに行う。

## 受け入れ条件

- [ ] 写真を選んでゴミ箱 →確認で「写真を削除」を押すと、ピンが消え、隣の写真が開く
- [ ] 最後の1枚を消すとパネルが閉じ、地図に写真が無い状態になる
- [ ] 「…」→「最近削除した項目」に、消した写真が出る。「元に戻す」で、元の位置・日時・メモのまま地図に戻る
- [ ] 一覧の「完全に削除」で、確認のあと、一覧から消える
- [ ] ペンで開いた編集シートで、日時・場所・タイトル・メモを直して保存すると、パネルに反映される
- [ ] 削除した写真が、並べ替え画面・隣の写真への移動に出てこない
- [ ] 7日を過ぎた写真が、アプリを開いたときに消えている(日時を動かして確認)

## やらないこと

- 一覧の「すべて戻す」「すべて完全に削除」(困ってから足す)
- 複数の写真をまとめて選んで消す操作
- 並べ替え画面からの削除
- 7日の長さをユーザーが変える設定

## 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| 入口 | 一覧は地図右上の常設「…」。削除と編集は、写真の右下の楕円(ペン+ゴミ箱) | 写真を選んでいなくても一覧を開ける。ボタンは3案を試して決めた |
| 確認 | 出す。Apple の写真アプリと同じ文言と形 | Apple のデザインに合わせる(ユーザーの指示) |
| 保持期間 | 7日 | ユーザーが選択(Apple は30日、当初の希望は1日程度) |
| 削除後 | 隣の写真へ、最後の1枚なら閉じる | 続けて消すときに開き直さずに済む |
| 一覧の操作 | 行ごとに元に戻す・完全に削除 | 必要になるまで増やさない |
| データ | `TripPhoto` に削除日時(`deletedAt`)を足す。軽量マイグレーション | 画像ごと残して隠すだけで済む |

## 影響

- 画面: `docs/specs/map-screen.md` に「…」メニューと確認を足す。新規に `docs/specs/recently-deleted.md`。
- モデル: `TripPhoto.deletedAt: Date?`。地図・並べ替え・位置の初期値は `deletedAt == nil` のものだけ使う。
- ADR: 「消さずに隠す(論理削除)」の判断を新番号で起票する(確定後)。
