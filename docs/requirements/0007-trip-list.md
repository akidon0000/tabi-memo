# 要件 0007: トリップの一覧画面

- 状態: 確認待ち(2026-10-11)
- 元の FB: [2026-10-11](../feedback/2026-10-11.md)(FB-18。ROADMAP の「トリップの一覧画面」から選んだもの)
- 読み手: 将来の自分・エージェント

## 困りごと

トリップは1つしか扱えない。起動すると、軌跡のあるいちばん新しいトリップの地図がすぐ開き、新しく作る操作も、ほかのトリップへ切り替える操作もない。旅ごとに分けて残せない。

## 要件

| ID | 内容 | 決めたこと |
|---|---|---|
| T-1 | 起動すると、一覧画面が開く | 一覧からトリップを選ぶと、いまの地図画面へ進む。地図には一覧へ戻るボタンを置く |
| T-2 | 一覧の各行 | トリップ名、期間(最初の写真〜最後の写真の日付。写真がなければ作った日)、表紙のサムネイル(最初の写真。なければ地図アイコン) |
| T-3 | 新しいトリップを作る | 一覧に「+」を置き、名前を入れて作る。作ると、そのトリップの地図が開く |
| T-4 | 名前を変える | 一覧の行から、トリップの名前を直せる |
| T-5 | 削除する | 一覧の行から消せる。写真と同じ期間(`PhotoRetention.days`、いま7日)は残して戻せる。戻す場所は、一覧の「…」→「最近削除したトリップ」。過ぎると完全に消える |
| T-6 | 空のトリップの地図 | 写真が0枚のときは、現在地の周りを出す。位置情報の許可がなければ東京 |
| T-7 | デモのトリップ | 新しくは入れない。すでに入っている端末では、ほかのトリップと同じ扱い(消せる) |

## 受け入れ条件

- [ ] 起動すると一覧が出る。行を押すと、そのトリップの地図が開く。地図から一覧へ戻れる。
- [ ] 一覧の行に、名前・期間・表紙が出る。
- [ ] 「+」で名前を入れると、新しいトリップができ、現在地の周りの空の地図が開く。そこに写真を追加できる。
- [ ] 名前を直すと、一覧に反映される。
- [ ] 削除すると一覧から消え、「最近削除したトリップ」に出る。そこから戻すと一覧に戻る。
- [ ] 複数のトリップのあいだで、写真・線・経由点が混ざらない。

## やらないこと

- 一覧の並べ替え・検索・フォルダ分け。
- トリップを複製する・結合する。
- 位置情報の記録(開始・終了)。

## 決めたこと・決めていないこと

| 論点 | 決定 | 理由 |
|---|---|---|
| 一覧の置き場 | 起動の入口 | 質問に対するユーザーの回答 |
| 行の内容 | 名前・期間・表紙 | 同上(写真の枚数は出さない) |
| トリップの操作 | 作る・名前変更・削除 | 同上 |
| 削除の扱い | 30日残して戻せる | 同上 |
| 空のトリップ | 現在地の周り。デモは入れない | 同上 |
| 一覧の並び順 | **未決定**。案: 作った日の新しい順 | 実機で見て決める |
| 地図から一覧へ戻るボタンの位置 | **未決定**。案: 左上。パネルや「…」と重ならない場所 | 実機で見て決める |
| トリップの切り替え方(「いまのトリップ」の持ち方) | **実装時に決める**。今の `ObserveCurrentTripUseCase` は「軌跡のある最新のトリップ」を返しており、これを「選んだトリップ」に置き換える | 実装の詳細 |

## 影響

- 新しい画面: トリップ一覧(`TripListFeature`)、「最近削除したトリップ」。地図画面は、選ばれたトリップを受け取る形に変える。
- モデル: `Trip` に論理削除(`removedAt`)を足す。写真の論理削除([ADR 0008](../adr/0008-soft-delete.md))と同じ考え方で、保存データの形が変わる。
- 残すべき ADR: 複数トリップと選択の持ち方(新番号で起票)。
- 前提が変わる記録: [ADR 0001](../adr/0001-map-screen-only.md)(地図画面だけ)、[map-screen.md](../specs/map-screen.md)。
